# v71 审阅报告：为什么仍然预测不准，以及下一步怎么改

日期：2026-10-12
对象：`phase68_runs/v71_qssa_asymptotic_exact`（训练）与 `phase68_runs/diagnostic_v68/split_test`（测试集验证）
方法：读训练日志、history、测试集 JSON/CSV；用 Cantera 重新生成轨迹对 checkpoint 做独立探针；用真实流水线（sampler → runner → split → train_sc_v68）在本机复现小规模训练并做对照实验。

## 一、结论

v71 的积分器重参数化和精确反演本身是对的，锯齿也确实消失了。模型仍然不准，主因是**训练根本没有学会**：从第 1 个 epoch 到第 20 个 epoch，速率损失一直停在 1.2 左右（标准化 MSE，等于只预测均值），oracle 单步状态 RMSE 停在 1.3 到 2.1。这不是网络容量或数据量的问题，而是两个可以精确定位的实现缺陷。

| 优先级 | 问题 | 证据 | 修复后效果（小规模复现） |
|---|---|---|---|
| P0 | 状态损失经过投影后取 log10，投影把微量物种钳到 0，导数 1/(Y ln10) 爆炸 | 状态损失梯度范数 2.5e16，速率损失梯度 8.8e-2，比值 2.9e17；clip 到 1.0 后速率梯度被完全淹没 | 只改 `--state-loss-source raw`，3 个 epoch 内 val rate 从 0.94 降到 0.089，val state 从 3.58 降到 0.008 |
| P0 | Dykstra 元素投影把宏观物种的微小误差摊给自由基，把自由基清零 | 宏观物种仅 1e-4 相对噪声时，H、HO2、NH2 在约 25% 的步上被压到 1e-30 以下 | 改为按 Y 加权的最小二乘投影后，1e-2 噪声下自由基零误差、零清零，元素残差从 1.6e-4 降到 7e-11 |
| P1 | 纯净初始混合物（自由基 Y=0）与冷冻冷态在输入上无法区分 | 复现库中 Y_OH≤1e-40 的行有 19,625 行，其中 19,516 行是冷态冻结，只有 38 行是高温即将着火 | 模型把高温纯净混合物也判为冻结，pure-AR 永远不点火 |
| P1 | 训练行分配严重偏向非反应段 | 着火轨迹平均 218 行，未着火轨迹平均 1,865 行；`|dT|>5 K` 的行只占 0.33% | 需在采样与损失两侧同时处理 |
| P2 | 宏观物种的 QSSA 逐物种独立预测，缺乏耦合 | 修复后 1500 K 工况 NH3 被消耗但 O2 几乎不动 | 需要守恒或反应进度耦合 |

## 二、训练为什么没有学会（P0-1：状态损失梯度爆炸）

### 现象

v71 history 中的关键指标（标准化空间）：

| epoch | H | train rate | train state | val rate | oracle H1 RMSE | pure-AR H128 |
|---|---|---|---|---|---|---|
| 1 | 1 | 1.223 | 3.036 | 1.487 | 1.320 | |
| 12 | 32 | 1.232 | 3.512 | 1.049 | 1.498 | |
| 16 | 128 | 1.224 | 3.444 | 1.452 | 1.695 | |
| 20 | 128 | 1.497 | 4.780 | 2.020 | 2.127 | 2.010 |

标准化目标的 MSE 等于 1 意味着模型输出与"永远输出均值"一样差。训练日志里还有 82 个 batch 因梯度非有限被跳过。

用 Cantera 新生成的 1300 K、40 atm 化学计量空气轨迹喂给 epoch 16 的 checkpoint，即使每步都给真值输入，潜变量误差也达到数十个数量级：

| 物种 | 预测 z1 中位数 | 目标 z1 中位数 | 预测 z2 中位数 | 目标 z2 中位数 |
|---|---|---|---|---|
| NH3 | -16.4 | -1.3 | -25.1 | 3.1 |
| O2 | -21.4 | -1.5 | -12.5 | 3.0 |
| OH | -21.0 | -6.3 | 38.5 | 8.2 |

预测值基本等于目标的数据集均值（例如 NH3 的 z1 均值是 -19.8）。

### 根因

`predict_next_state` 在 qssa_asymptotic 分支之后无条件调用 `project_physical_state`。投影里的 `clamp(min=0)` 会把大量微量物种钳到 0，随后状态损失取 `log10(clamp(Y, 1e-40))`。在 Y 接近 1e-40 处，log10 对 Y 的导数是 1/(Y ln10)，约 1e39。

在本机用真实流水线生成的小库上，同一个 batch、同一个初始化网络：

| 量 | 数值 |
|---|---|
| 速率损失对参数的梯度范数 | 8.8e-2 |
| 状态损失对参数的梯度范数 | 2.5e16 |
| 两者比值 | 2.9e17 |
| 两个梯度的余弦 | -0.01 |
| 投影后微量物种低于 1e-30 的比例 | 34% |

`clip_grad_norm_(max_norm=1.0)` 之后，有效梯度几乎全部来自状态损失的这几个病态元素，方向与拟合目标无关。速率损失的梯度被缩小了 17 个数量级，相当于没有训练。

### 对照实验（同一数据、同一网络、1,500 步）

| 设置 | 最终 rate | 最终 state |
|---|---|---|
| 仅速率损失 | 0.011 | 1.838 |
| 速率 + 投影后状态损失（v71 现状） | 1.414 | 2.467 |
| 速率 + 投影后状态损失，不裁剪梯度 | 1.357 | 2.593 |
| 速率 + **积分器原始输出**上的状态损失 | **0.014** | **0.001** |
| 速率 + 投影后状态，但取 log10(Y+1e-30) | 0.088 | 1.461 |

结论：状态损失必须作用在积分器原始输出上，投影只用于反馈，不参与反向传播。只加一个软下限不够，因为投影本身在破坏信息（见下一节）。

### 用真实训练脚本验证

在小库上直接运行 `train_sc_v68.py`，除 `--state-loss-source` 外参数完全相同：

| epoch | constrained（v71） val rate / val state | raw val rate / val state |
|---|---|---|
| 1 | 1.158 / 2.848 | 0.148 / 0.0175 |
| 2 | 1.580 / 3.745 | 0.115 / 0.0132 |
| 3 | 0.942 / 3.575 | 0.089 / 0.0082 |

再把反馈也改成 raw，并开启 H=8、32 的课程：

| epoch | H | val rate | oracle H8 | pure-AR H32 | 跳过 batch |
|---|---|---|---|---|---|
| 4 | 8 | 0.150 | 0.064 | | 0 |
| 6 | 32 | 0.136 | 0.058 | 0.189 | 0 |
| 8 | 32 | 0.098 | 0.049 | 0.155 | 0 |

同样配置下若反馈仍用 constrained，H=32 时 oracle H8 会从 0.14 恶化到 126。v71 全量训练的 pure-AR H128 是 2.01，修复后的小模型在 H32 是 0.155。

**这两项改动只需要命令行参数，不改代码**：

```
--state-loss-source raw --feedback-state-source raw
```

## 三、投影在清除自由基（P0-2）

把 Cantera 给出的**精确** Y_next 送进 `project_physical_state`，只在 5 个宏观物种上加一点相对噪声。理想投影应当不动自由基。

单元格为"中位 |Δlog10 Y| / 120 步中被压到 1e-30 以下的步数"：

| 宏观噪声 | OH | H | O | HO2 | NH2 | N2O | H2O2 |
|---|---|---|---|---|---|---|---|
| 0 | 0.00/2 | 0.00/1 | 0.00/2 | 0.00/0 | 0.00/0 | 0.00/2 | 0.00/1 |
| 1e-4 | 0.00/16 | 0.11/26 | 0.06/19 | 0.11/15 | 1.09/30 | 0.07/31 | 0.45/31 |
| 1e-3 | 0.02/26 | 1.76/29 | 0.87/31 | 0.75/26 | 2.48/42 | 0.29/47 | 1.69/43 |
| 1e-2 | 0.50/28 | 31.4/56 | 4.66/52 | 2.57/51 | 3.77/48 | 34.0/70 | 18.1/53 |

原因是欧氏距离下的仿射投影对每个物种施加同量级的绝对修正。宏观物种 1e-4 的误差约等于 1e-5 的绝对量，对 1e-6 量级的自由基就是 10 倍以上的修正，随后非负截断把它们清零。这也解释了测试集里 oracle 路径 68% 的行被投影干预，以及 Gemini 报告中"自由基被压在 1e-21"的现象。

改用按物种当前浓度加权的投影（最小化 Σ ΔY_k²/Y_k，约束为元素守恒与总质量守恒），有闭式解：

```
ΔY = W Aᵀ (A W Aᵀ)⁻¹ r,   W = diag(Y_raw),   r = b − A Y_raw
```

同一测试中的结果：

| 宏观噪声 | 加权投影：所有自由基 | 最大元素残差（Dykstra → 加权） |
|---|---|---|
| 1e-4 | 0.00 / 0 次清零 | 8.2e-7 → 2.7e-11 |
| 1e-3 | 0.00 / 0 次清零 | 5.7e-6 → 6.9e-11 |
| 1e-2 | 最大 0.01 / 0 次清零 | 1.6e-4 → 7.0e-11 |

修正量与浓度成正比，所以微量物种天然不会变负，不需要迭代，也不需要非负截断。建议用它替换 `project_physical_state` 里的 Dykstra 循环。替换后可以重新考虑用 constrained 反馈，因为这时投影不再伤害自由基。

## 四、为什么修复后仍不点火（P1）

修复后的小模型在 oracle 下能正确跟随着火（1300 K 工况，第 33 步起 OH、NO、NH3 与真值一致到小数点后两位）。但 pure-AR 从 t=0 开始时永远不点火。

### 纯净混合物与冷冻态在输入上重合

LHS 采样的初始状态对绝大多数自由基为 0。输入特征是 log10(max(Y, 1e-40))，所以 1300 K 的纯净混合物和 500 K 的冻结混合物在自由基维度上完全相同，都是 -40。训练库中这两类行的数量：

| 类别 | 行数 |
|---|---|
| Y_OH ≤ 1e-40，T < 900 K，下一步仍 < 1e-30（冻结） | 19,516 |
| Y_OH ≤ 1e-40，T > 1100 K，下一步 > 1e-15（即将着火） | 38 |

第一步的预测因此退化为"保持 1e-40"，此后每一步输入都是同一个冻结状态，自回归无法自我恢复。把 pure-AR 改为从真实第一步之后开始时，1500 K 工况在着火时刻后 3 步开始放热，NH3 在第 30 步降到 7.8e-7，说明模型已经学到着火化学，缺的只是"从零起步"这一行为。

### 行分配偏向非反应段

小库里着火轨迹每条平均 218 行，未着火轨迹每条平均 1,865 行；`|dT|>5 K` 的行只占 0.33%。`unignited_timeout` 让冷态轨迹一直跑到 0.25 s 才停，产生大量信息量为零的冻结行。

## 五、建议的修改顺序

### 第一步：只改命令行参数，验证收益（0 代码）

```
python train_all_v68.py --plan v71_qssa --state-loss-source raw --feedback-state-source raw
```

预期 rate loss 在前几个 epoch 内降到 0.1 量级，不再停在 1.2。

### 第二步：替换投影（约 30 行代码）

在 `project_physical_state` 中用浓度加权的闭式投影替换 Dykstra 迭代。验收标准：

- 上一节的噪声测试中，1e-2 宏观噪声下自由基零清零。
- 元素残差优于 1e-9。

完成后把状态损失保持在 raw 输出上，反馈可改回 constrained。

### 第三步：解决"从零起步"问题

任选其一或组合：

1. **自由基种子**。在 runner 和推理时，对 Y=0 的反应性物种赋一个物理下限，例如 1e-20，并在输入特征中把 log10 下限从 -40 提到 -20。这样纯净混合物在输入上仍是唯一的，但模型的第一步需要学的是"从 1e-20 增长"，与诱导期行为连续。
2. **加一个指示特征**。为每个微量物种增加"是否低于下限"的二值输入，并把温度信息直接参与判定。
3. **对首步加权**。在损失中对 t=0 行与高温低自由基行提高权重，例如乘以 10 到 50。

建议优先做 1，它同时改善 runner 精确反演中大量 P=0、D=0 的哨兵标签。小库中宏观物种有 17% 到 34% 的行落在 -45 哨兵上，这些行主要来自 float64 分辨率以下的冻结步。

### 第四步：重新平衡数据

- 将 `max_unignited_time` 从 0.25 s 降到估计着火延迟的 2 到 3 倍，或对冻结段做按信息量的下采样。
- 在 DataLoader 中按 `|dT|` 或 `|Δlog Y_OH|` 做重要性采样，使着火转变行的比例达到 5% 到 10%。
- 现有的 `transition_weight_alpha` 只放大 2 到 8 倍，不足以弥补 300 倍的行数差距。

### 第五步：宏观物种耦合（中期）

修复后 1500 K 工况中 NH3 被消耗但 O2 基本不动，说明 5 个宏观物种的独立 QSSA 参数不一致。短期可以靠加权投影把元素守恒强制回来。长期仍建议按计划 Phase 2 引入反应进度或化学计量约束，让宏观物种的变化由少量反应速率共同决定。

### 验证口径

- 选模用 pure-AR 的 IDT 误差和 OH 峰值时刻，不要用标准化 RMSE。v71 的 best_total 是 epoch 1，因为 epoch 1 之后模型越来越差，标准化总损失无法反映这一点。
- 测试 pure-AR 时必须从 t=0 的纯净混合物开始，否则会掩盖"从零起步"的问题。

## 六、对两份已有报告的校正

- **Gemini 报告前半部分**称 epoch 16 所有物种误差低于 0.8%、锯齿彻底消失。线性 RMSE 小是因为大部分行是冻结的冷态，模型只要不动就对。测试集的 `active_log_rmse` 显示 OH 在 oracle H1 就有 8.7 dex 误差，pure-AR H128 有 21.5 dex。
- **Gemini 报告后半部分**把原因归于 MSE 的非对称惩罚与"过阻尼防御陷阱"。实测根因是状态损失梯度爆炸和投影清除自由基，属于实现缺陷，不是优化目标的固有性质。提出的"着火激发专项损失"在梯度爆炸未修复前不会起作用。
- **GPT 报告**对"稳定但不准"的判断正确，对投影干预率的数字也正确。建议锁定 epoch 16 继续研究这一点不成立：epoch 16 的模型输出接近目标均值，不值得作为后续基础，应在修复后重新训练。


复现库有 150 条轨迹、16.8 万行，单次 3 个 epoch 的训练在本机 GPU 上约 1 分钟。
